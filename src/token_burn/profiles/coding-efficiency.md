# Coding efficiency

Use the owning repository's authority, scope, safety rules, and required validation.
This profile supplies working habits, not permission to take an action.

- Start from the named owner and affected paths. Read applicable instructions once
  completely, then retrieve only changed or missing sections. Search precise names
  and inspect targeted excerpts before broad discovery. Use the existing skill
  discovery owner when a specialist is needed; do not load an entire catalog.
- Capture noisy authorized commands once with `token-burn capture`. Keep full
  evidence privately and return the exit status, counts, and useful facts. Use
  `token-burn read` to inspect saved pages instead of rerunning a command for output.
  A command's exit status does not prove that the user's workflow is accepted.
- Keep handoffs compact and explicit: objective, authority, stop conditions,
  changed files, validation state, receipts, active processes, blockers, and next
  action. Use `token-burn handoff create` and `validate` when handing off. Preserve
  every protected field; reference private evidence without replaying whole logs.
  A handoff carries context, never additional authority.
- Name one owner for final validation. Run required checks at the required
  revision. Repeat them when inputs change, a failure occurs, or freshness is
  required. Retain failed attempts and required negative controls.
- Do not repeatedly poll or reread unchanged healthy state. Use an available wait
  mechanism or return a clear next action. Explain blockers and request the exact
  missing evidence instead of repeating a failed operation without a new reason.

Measure whole tasks, including retries, children, continuations, and required
validation. Keep quality gates fixed. Missing usage is unknown. Only describe
token savings when complete matched-task evidence supports that conclusion.
